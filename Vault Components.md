# Vault Components

Obsidian is a general-purpose note-taking application, but it can be adapted extensively for use as a laboratory notebook for synthetic organic chemistry. This vault is built around that adaptation, i.e. around a specific laboratory workflow.
The vault combines published community plugins and CSS snippets with plugins that have not been published in the Obsidian Community Plugins store.

## Keep only what you need

Every plugin in this vault solves a specific task. For the fastest startup and smoothest work, keep the number of enabled plugins to a minimum and the workflow as simple as possible: the simpler the journal, the faster and more convenient it is to use. Plugins can be disabled at any time in **Settings → Community plugins** without deleting any notes.

- **TLC Photo Inbox** can be disabled if you do not transfer photos from your phone through Telegram.
- **CDX Scheme Image** can be disabled if you draw reactions neither in ChemDraw nor in Reactio Draw, or prefer to insert reaction images yourself.
- **NMR Downloader** can be disabled if your NMR spectra do not arrive by e-mail (its **Open in TopSpin** button works without the mail settings; see [[NMR Downloader guide]]).
- **Template Guard** can be disabled if you do not want the template parts of reaction notes to be protected and checked.
- **Dataview Serializer** can be disabled if you do not freeze Dataview tables; Chemistry Word Report does not need it.
- **Chronology Custom** can be disabled if you do not use the calendar with note statistics.
- **Kanban Day Planner** and **Kanban** can be disabled if you do not plan your work with Kanban boards.

If you disable a plugin whose view is open in the right sidebar (Kanban Day Planner or Chronology Custom), simply close that empty tab.

If your tasks are different, you can install other plugins in addition to, or instead of, those included here.

Obsidian can be customized in three ways: scripts, CSS snippets, and plugins.

## Scripts

The **Scripts** folder contains the `idnext` file, which keeps the numbering of reaction notes consistent. It is used by the project templates and by the template that generates them, [[dont delete - template for project templates]]. When a new project is created with [[add project]], the `idnext` file is duplicated (`idnext1.js`, `idnext2.js`, …), because every project has its own identifier and therefore needs its own `idnext` file. In the example vault, `idnext1.js` belongs to the `Exp_` project.

## Plugins

Obsidian has two types of plugins: **core plugins**, which are developed by the Obsidian team, and **community plugins**. Because our use case is highly specific, this vault relies on both core and community plugins; in addition, several custom plugins had to be written to cover needs that existing plugins did not address.
Core plugins are not discussed here.

### CDX Scheme Image
*Developed for this vault* (not in the Obsidian community plugin directory; included in the vault). A plugin that automatically keeps the reaction note synchronized with its ChemDraw file. It watches the **Files** folder for new and changed ChemDraw files, both `.cdx` and `.cdxml`. Keep only one file per reaction: if `A_141.cdx` and `A_141.cdxml` both exist, the newer one is used and a warning asks you to delete the other. Whenever `A_141.cdx` is saved in ChemDraw, the plugin draws the reaction scheme together with ChemDraw's reagent table using the drawing settings saved in the file (bond length, line widths, spacing and font sizes — for example ACS Document 1996; text is drawn in Arial; these ACS values are used only if the file has none), keeps colors, highlighting and ring fills as drawn in ChemDraw, saves the picture as `A_141 scheme.svg` next to the `.cdx` file, and places it on the line after **Table** in note `A_141…` (every note in the Journal folder whose name is `A_141` or begins with `A_141 `, upper/lower case ignored; if there is no such note, the only note that links to `A_141.cdx`). Any project code works (`A_`, `IN_`, `Exp_`, `PAS_`, …). Every later change in the ChemDraw file — new masses, equivalents, yield — appears in the note after saving, also in a note that is already open. If another image already follows **Table**, it is replaced; the old image file is not deleted and can be removed with Clear Unused Images Plus. ChemDraw itself is not needed for drawing: the plugin reads the structures, arrows, captions and the already calculated table values stored in the `.cdx` file and shows only the table values that ChemDraw shows. Files saved while Obsidian was closed are redrawn at startup. When the plugin is first enabled, existing notes are left unchanged (only ChemDraw files saved after that are drawn automatically): an image appears when the `.cdx` file is saved again, or after the command **Update scheme image in current note**. If the reaction in the file has exactly one product, the plugin also draws this product alone as `A_141 product.png` and puts it into the existing `pic::` field of the note (for example `**pic**::![[A_141 product.png|300]]`; the width can be changed in the plugin settings); this picture is used by Chemistry Word Report, which is why it is always a PNG. A note without a `pic::` field is not changed, and files with several products (or several reaction steps) leave `pic::` as it is. This can be turned off in the plugin settings (**Product image in pic::**). In the same case the yield of the product from the reagent table, rounded to a whole percent (56.70 % → `57%`; below 1 % with one decimal, `0.4%`), is written into the `yield::` field, and the measured product mass into `mass::` (as the table shows it, without trailing zeros: below 1 g in mg, `71 mg` or `25.7 mg`; from 1 g on in g, `2.06 g`): an empty field or a number is replaced, text typed by hand (`n.r.`, `traces`, `not isolated`) is kept, a product mass corrected to 0 gives `0%`, and a number the plugin wrote is cleared when the yield or mass is removed from the table (a number of unknown origin, e.g. typed by hand, is kept and a notice asks to check it) (settings **Yield in yield::**, **Product mass in mass::**). The molecular weight of the product, as the table shows it (`432.35`), goes into the `MW::` field by the same rules (setting **MW in MW::**); Chemistry Word Report uses it only for the optional calculated mass `[[calcmass]]`. Reaction conditions go into the `temperature::`, `time::`, `atmosphere::` and `other::` fields when the file has a caption with the lines *Temperature: …*, *Time: …*, *Atmosphere: …*, *Other: …* (Reactio Draw writes it; typed like this in ChemDraw it works too): an empty field is filled, a value written from the file before is updated, a value typed by hand is kept (setting **Conditions in temperature::, …**). For the HRMS request, the product is also drawn as `A_141 mass.png` with *Chemical Formula*, *Exact Mass* and *m/z* (isotope peaks of at least 1 %) under it, as in ChemDraw's Analysis window, and put into the `Mass_pic::` field when that field is empty or already shows this picture; a picture you inserted yourself is kept (setting **Mass picture in Mass_pic::**). A ChemDraw file that contains nothing to draw never replaces an image. The blank file `Open CDX Editor.cdx`, which is linked from all templates, is listed under **Excluded files** in the plugin settings and is never drawn. A note without a **Table** line gets no image (a notice says so). CDXML files saved by the web reaction editor (they carry its own record) get that editor's table layout: separate Reactants and Products tables with a role header, values with units, and a Conditions table. Folders, image format (SVG or PNG), PNG resolution, background, the image name suffix (` scheme`), replacing an existing image and the update at startup can be changed in the plugin settings. Desktop only.
### Chemistry Word Report
*Developed for this vault* (not in the Obsidian community plugin directory; included in the vault). It generates a draft of the Supporting Information from reaction notes. The notes are taken from the Dataview query in the active note (through the Dataview API, without temporary files) or, if the note has no query, from the links in the first column of a Markdown table in it. The product mass (`[[mass]]`) is the weighed mass from the note's `mass::` field, which CDX Scheme Image fills from the reagent table (in `[[mass]] mg`, a mass of 1 g or more is written in g: `2.06 g`); `[[calcmass]]` gives the mass calculated from MW, scale and yield instead. Nothing is filled in silently: a missing mass, scale, procedure or ionization appears as a placeholder such as `[mass not recorded]` or `[scale]`, and the notice after the report lists the notes concerned (defaults set by you in the plugin settings are still used). NMR data pasted together with its header (`1H NMR (500 MHz, C6D6) δ …`) is accepted: the header is replaced by one made from `frequency::` and `solvent::`, and the notice lists a pasted header whose nucleus, frequency or solvent differs from the note. An example is described in [[Welcome note#Creating a Draft of the Supporting Information]].
### Chronology Custom
*Modified for this vault.* A modified version of the published Chronology plugin. It visualizes statistics on how many notes were created and edited. It is used mainly in the right sidebar, opened with the **Show sidebar** command. Each calendar day is colored according to the number of notes; the target number of notes is set in the plugin settings. Because the plugin lists the notes created and edited on the current (or selected) day, it is also a convenient way to reopen today's notes.

### Clear Unused Images Plus
When a reaction note is created, the reaction scheme and the calculation table are inserted as an image. After the reaction is finished, the yield and the mass of the isolated product must be added to the table, so the image has to be replaced (with a CDX or CDXML file, CDX Scheme Image does this automatically, but a previous image may remain in the **Files** folder). To avoid accumulating old, unused images, this plugin deletes them with one click on its icon in the left ribbon. The `docs` folder, including its subfolders, is excluded in the plugin settings, because the screenshots used by the GitHub README are not linked from any note and would otherwise be deleted; `Files/telegram` is excluded too, because photos from the TLC Photo Inbox bot wait there, not yet linked, until they are added to a note.

### Dataview
Used to build automatically assembled tables, for example a reaction [[Scope]] table or an [[Optimization]] table. Learn more about Dataview [here](https://publish.obsidian.md/hub/04+-+Guides%2C+Workflows%2C+%26+Courses/Guides/An+Introduction+to+Dataview). It is also required when a Chemistry Word Report or an ORD/PubChem export is run from a Dataview query (not for a hand-written table of note links).
### Dataview Serializer
Saves the result of a Dataview query as static Markdown. In Markdown files, Dataview tables and lists are stored only as queries, and their results are displayed only inside Obsidian. It is optional: use it when you want to keep a fixed copy of a table, for example the list of compounds that went into a given Supporting Information. The Chemistry Word Report plugin does not need it; it reads the query result through Dataview directly, and it can also use such a frozen table.
### Filename Heading Sync
Keeps the note file name and its first heading synchronized. In this vault it is limited to notes in the **Journal** folder (setting *Ignore regex*: `^(?!Journal/)`), so that the README, licenses, and other documentation files are never renamed. This makes it possible to add a short comment to the name of a reaction note. It also displays the note name prominently when the note is opened; without it, the file name appears only in small type in the top bar. Overall, it makes several things visually cleaner.

### Meta Bind
Adds buttons to notes that run various commands. For example, the reaction-note template contains three buttons: **Finish**, **add NMR**, and **add mass**. These buttons use the Templater plugin to run the files [[add_nmr]], [[add_mass]], and [[finish_note]].

- **Finish** moves the note to the folder with finished reactions.
- **add NMR** adds an NMR spectrum entry to the [[NMR Journal]] table. The compound structure for the table is taken from the `pic::` field, if it is filled in; the remaining information is taken from the answers entered in a pop-up dialog. The solvent is chosen from a list (CDCl3, DMSO-d6, D2O, DCM-d2, acetone-d6, methanol-d4, benzene-d6); **Other…** at the end of the list lets you type any other solvent or a mixture (CD3CN, THF-d8, `CDCl3/CD3OD 9:1`). The spectra are chosen one by one from a second list until **Done**; its **Other…** adds an experiment that is not listed (TOCSY, ROESY, 11B, 29Si), as often as needed, and it is ticked in the journal after the listed ones. The NMR Journal helps you keep track of your NMR experiments.
- **add mass** adds an HRMS measurement entry to the [[Mass Journal]]. For it to work, the **Mass_pic**:: field must contain an image showing the compound structure and its molecular formula (e.g., C6H12O6). With a ChemDraw file of one product, CDX Scheme Image fills this field automatically. The image is inserted automatically into the table and into the measurement request form in an Excel file, which is then printed. This button was built for the workflow of a specific mass-spectrometry facility; you can adapt it to your own workflow by modifying the [[add_mass]] file. All settings are collected at the top of [[add_mass]]: the sample code (`MASS_CODE`, `PAS` by default), the Mass Journal and Excel template paths, the form cells, and the image widths. For use within the Technion, it is sufficient to set `MASS_CODE` to your own code, change the same prefix in cells E3 and B6 of `Files/MS_FORM.xlsx`, and enter your details in that Excel file.
### NMR Downloader
*Developed for this vault* (not in the Obsidian community plugin directory; included in the vault). A plugin that collects NMR spectra sent by the NMR service by e-mail. Press the download icon in the left ribbon (or run the command **Download NMR spectra**): the plugin reads the unread Gmail messages from the configured sender address, saves the attached `.zip` archives whose names contain your user name, unpacks each archive named `PREFIX_NAME<MHz>-<year>_<number>.zip` (for example `MG_Pavel400-2026_12.zip`; other archives stay in the download folder) into the folder set for its spectrometer frequency (or into one folder, or both), and opens the spectra (`1r`, `2rr` or `acqu`) in MestReNova. A mail is marked as read only after its archive was unpacked (one without an archive for you, or whose archive could not be unpacked, stays unread). Only the archives downloaded in this run are unpacked; the `.zip` is then deleted unless **Keep the .zip after unpacking** is on. By default, experiments 10–19 of one spectrometer open together in one new MestReNova document, 20–29 in the next, and so on; they can also be opened one by one (setting **MestReNova documents**). Mail is read through the Gmail API: a `credentials.json` file from your own Google Cloud project is created once and must stay at the path set in the plugin (it is read on every run), and the **Authorize** button signs you in to Google in the browser. The sign-in token, the Google account address and the path to `credentials.json` are kept on this computer only, outside the vault, and the token is encrypted by the operating system where available; each computer signs in once, and **Sign out** revokes the access. The plugin connects to Google only when you run it. Step-by-step setup is described in the plugin's `README.md` (in `.obsidian/plugins/nmr-downloader/`). Desktop only. The experiments of one sample (10–19, 20–29 …) are unpacked into one folder (setting *Folders by tens*). The spectra can also open in **Bruker TopSpin** instead (setting *Open downloaded spectra in*): the whole folder of the sample, each experiment in its own TopSpin window, and TopSpin is started if it is not running; the command **Open a Bruker spectrum folder in TopSpin** opens any experiment folder, or a folder with several, and processing done in TopSpin stays in the spectrum folder. The **Open in TopSpin** button in the NMR section of a reaction note (command **Open the NMR spectra of this note in TopSpin**) opens the spectra listed in the note's `NMR_id` field (several numbers separated by commas, e.g. `7180, 7190`): each number names the first experiment of a sample, and its sample folder (or experiments 7180–7189 of spectra unpacked without *Folders by tens*) is found in the spectra folders of the plugin; a `frequency` value in the note limits the search to that spectrometer's folder. Optionally (setting *Spectrum folders named after the notebook page*) the button opens the folders named after the notebook page instead, such as `0100150101` for `Exp_15` in notebook `01`. Step-by-step setup and use: [[NMR Downloader guide]].
### Open Files Directly
*Developed for this vault* (not in the Obsidian community plugin directory; included in the vault). **Off in the downloaded vault: turn it on once in Settings → Community plugins.** Since version 1.15, Obsidian asks *Open file in another app? This file will open outside of Obsidian…* before it opens a file type it does not know, so a link to a reaction file (`.cdxml`, `.cdx`) or a MestReNova document (`.mnova`) opens only after a second click. With this plugin the listed types open in their program with one click — from a link or an embed (`![[A_437.cdxml]]`) in Reading view or Live Preview, the file explorer or the quick switcher — as with Obsidian's own *Open in default app* menu item. Settings: **File types** (default `cdx, cdxml, mnova, pdf`; PDF opens inside Obsidian anyway) and **Folder** (default `Files`, with its subfolders): the same types elsewhere in the vault keep Obsidian's question. Programs, scripts, web pages, SVG, Office files with macros and disk images are never opened this way, even when listed, and Obsidian still asks before it runs anything executable. No network access. Desktop only.

### Reactio Draw
*Developed for this vault* (the Obsidian wrapper; [Reactio Draw](https://github.com/Paivel/reactio-draw) itself is a separate free program under the Mozilla Public License 2.0, version 1.15.2 embedded unchanged, archived on Zenodo, [DOI 10.5281/zenodo.23547490](https://doi.org/10.5281/zenodo.23547490); its Windows, Mac and Linux apps are downloaded from its GitHub releases). Opens the Reactio Draw editor in an Obsidian tab (pencil button in the left panel, or the command **Reactio Draw: Open a new drawing**). Use it to:
- **draw the reaction of a reaction note with its reagent table** — click the picture *Click to draw the reaction and the table* under **Table** in a new note: `Files/A_122.cdxml` is created (the code is the first part of the note name) and opened in Reactio Draw. Draw, then press **Ctrl/Cmd+S** or **Ctrl/Cmd+W** (or close the tab with ×): the file is saved without a question and the tab closes, and CDX Scheme Image puts the scheme with the table under **Table** in place of the placeholder. Click the scheme later to edit it again. The file is ordinary CDXML, so ChemDraw and the Reactio Draw app open it too. If the reaction is a ChemDraw `.cdx` file, nothing changes: open it from its link as before. With the setting *Open reaction files in* → *Default program outside Obsidian*, the click creates the blank `A_122.cdxml` and opens it (or an existing `A_122.cdx`) in the program your system uses for these files, such as ChemDraw, instead of a Reactio tab;
- **draw search queries** — draw a structure or a reaction and press the search button at the top of the tab; the search dialog of Reaction Structure Search opens;
- **draw your own schemes in notes** — press the picture button at the top of the tab: the drawing is saved in **Files** as a `.rdraw` file (a picture with the drawing inside) and `![[… scheme.rdraw]]` is inserted at the cursor of the last note you worked in. The note shows the picture; **click it** to edit the drawing in Reactio Draw; **Save** updates the picture everywhere it is shown. Add a width as for images: `![[… scheme.rdraw|300]]`;
- **names** — 3D shapes, NMR prediction and *Structure from a name* (common and systematic names, CAS numbers) work in the tab as in Reactio Draw itself, offline. IUPAC names of drawn structures (*Name the selected structure*) need the installed Reactio Draw app, which the plugin finds in its usual place (or set its path in the plugin settings);
- **save drawings as CDXML** in the **Drawings** folder (ChemDraw opens them; Reactio Draw reads them back in full).
- **open Reactio Draw documents** (`.reactio`, as the Reactio Draw apps save them) kept in the vault: right-click the file → *Edit in Reactio Draw*; Save writes it back in place.

A drawing opened from a note is saved when its tab is closed; a new drawing is saved only with **Save** (● in the tab title marks unsaved changes). While a Reactio tab is open, the side panels are hidden and come back when it is closed. ChemDraw `.cdx` files of reaction notes keep opening in ChemDraw, and CDX Scheme Image works with them as before.
### Reaction Structure Search
*Developed for this vault.* Searches the reaction notes by compound structure or by reaction.
In the **Reaction Structure Search** plugin settings, select the folder containing your journal notes and the folder containing your ChemDraw files (`.cdx` or `.cdxml`; if both exist for one reaction, only the newer one is searched and a warning is shown). The search runs locally and does not require an internet connection. Results are shown 50 at a time (**Show more** for the next ones); a long search shows its progress and can be stopped with **Cancel**.

  ![[Welcome-note-12.png]]

  To build a query, open Reactio Draw with the pencil button in the left panel. Draw a product, reactant, or complete reaction, then click the search button in the upper-right corner of the drawing tab. Select the desired search modes and click **Search**. Click a note name in the results to open it.

  **Exact** search compares whole molecules; **substructure** search finds structures that contain the drawn fragment. Hydrogens drawn as separate atoms (for example, H at a ring fusion) are made implicit. Stereochemistry is read from the wedges and hashed wedges in ChemDraw and from the drawn geometry of double bonds. By default (**any stereo**) a structure is found however its stereocentres were drawn; in **exact** mode you can instead choose **relative stereo** (the same configuration or its mirror image, useful for racemates such as cis/trans diastereomers) or **absolute stereo** (exactly as drawn). Substructure search ignores stereochemistry. Chemical abbreviations are resolved with **BChemLookup**, the open abbreviation table of the Beilstein-Institut (CC0; Bänsch, Rajan, Nietfeld, *ChemRxiv* 2026, [DOI 10.26434/chemrxiv.15010166/v1](https://doi.org/10.26434/chemrxiv.15010166/v1)): a label that ChemDraw itself could not interpret (for example `OTr` or `NPhth` typed as plain text) is replaced by its structure, and reagents written as text above or below the arrow (`THF`, `Et3N`, `K2CO3`) are found by structure search too. Names that are not in the table (e.g. Pd(PPh3)4, Pd/C) are not recognised — draw such reagents as structures or with ChemDraw's own abbreviations. Labels that are not one table entry are read as condensed formulas (`NBpin`, `CH2CH2OH`, `CO2tBu`, `N(iPr)2`, `HO`, `O2N`). A label that still cannot be read, and generic labels such as R or X, are kept as "*" (never as carbon): such a structure is not an exact hit, and a substructure hit is marked *label not interpreted* — expand the label in ChemDraw (right-click → Expand Label) or draw the group. The search index is stored in `.reaction-index`; it is updated for changed files, rebuilt automatically when a plugin update changes how structures are read, and can be rebuilt with the command **Rebuild reaction search index**.

![[Welcome note-62.png|387]]

  In the results you can tick notes (or **all**), type a tag and press **Add tag**: the tag is added to the tags of each picked note, for example to collect the reactions of a paper (`paper-2026`) for a Supporting Information draft or an ORD export.

  **ORD export.** The same plugin can export reactions as a dataset of the [Open Reaction Database](https://open-reaction-database.org) (ORD), so that the reactions of a paper — including failed ones — can be published in a standard, machine-readable form. Run **Export ORD dataset from current table** in a note with a Dataview query whose rows link to reaction notes (the same kind of table as for Chemistry Word Report), or **Export current note to ORD** in one reaction note. For each note the plugin reads its ChemDraw file and note fields:
  - structures from the ChemDraw file as SMILES with the stereochemistry drawn with wedges (a product whose `Name::` marks a racemate, such as `(6bSR,10aRS)-…`, `rac-` or `(±)`, is marked *racemic*, and one named `rel-` as a relative configuration with the absolute configuration unknown; generic labels such as R or Ar cannot be exported), with the amounts shown in ChemDraw's reagent table;
  - reagents written as text above or below the arrow, if their name is in BChemLookup and the amount is written next to it: `Et3N (2 equiv), THF (2 mL)` — mL, mg and mmol are taken as written, equiv and mol % are converted with `scale::` (mmol). Conditions in the same text (`rt`, `0 °C`, `12 h`) are skipped; a name without an amount, or one not in the table, is listed as a warning and not exported;
  - amounts: everything comes from the reagent table — the amount (mass, moles or volume) and, as extra values of the compound, the mass, volume and molarity shown there (for a solvent no molarity, and a mass only when a density is given). A reagent written as text in Reactio Draw (MeCN, THF, MeMgBr) is exported from its column in the table with the name from Reactio Draw (its structure comes from the one attached to the text in Reactio Draw, else from the name: the solvent list, BChemLookup or the plugin's list of common reagents such as MeMgBr; a name without a known structure is exported by name and formula, with a warning). A counter-ion written as text next to a drawn cation (`PF6-` of a salt) is joined to it: the salt becomes one compound, cation.PF6-, with the amounts of its column; search finds these text reagents too; a solution ("3.00 M in THF") also lists its solvent; a salt that Reactio Draw splits into cation and anion is exported as one compound;
  - roles: products are right of the arrow; in files saved by Reactio Draw the role chosen in its reagent table is used for *catalyst* and *solvent*; *reactant* is Reactio Draw's default, so for it the rules below decide; ChemDraw files and files without roles use the rules alone. For the other components the plugin decides — a listed solvent given as a volume is a solvent, a transition-metal compound at ≤ 0.2 equiv a catalyst, the limiting reagent and compounds whose skeleton appears in the product are reactants, everything else gets the default role (Settings → *ORD export* → *Default role*; *unspecified* in this vault). Correct a wrong guess with a line such as `roles:: MeMgBr = reagent; Pd(PPh3)4 = catalyst` in the note: name each component as the export report lists it (the label on the scheme, such as MeMgBr or THF, otherwise the formula from the reagent table, such as C6H8O7, otherwise `structure <number>`), followed by `=` and reactant, reagent, catalyst, solvent or workup; separate several with `;`. *workup* is for a quench added after the reaction, such as the citric acid in IM_1 (`roles:: MeMgBr = reactant; C6H8O7 = workup`): it is exported as a workup step (ADDITION) instead of a reaction input;
  - from the note: `yield::`, `Date::`, `state::` (colour and texture), the NMR and HRMS fields, optionally the **Procedure** section (setting *Include procedure text*, off by default), and the new fields `temperature::` (e.g. `25 °C`, `-78 °C`, `rt`, `reflux`), `time::` (e.g. `16 h`, `30 min`) and `atmosphere::` (`Ar`, `N2`, `air`); a missing or empty field is taken from the reaction file (the *Temperature / Time / Atmosphere* caption that Reactio Draw writes, else its record), and the export report says where each value came from; with no value anywhere, nothing is assumed: the condition is left out of the record and listed as *not recorded* in the report. `yield:: 0`, `n.r.` or `traces` exports a failed reaction; `n.d.` means not determined (no yield). The order of addition is not recorded in the notes and is not exported;
  - purification: `workup::` (or `purification::`) and `eluent::` become one workup step after the additions marked *workup*. When `workup::` says chromatography (`workup:: flash chromatography on silica gel`), the step is FLASH_CHROMATOGRAPHY with the eluent; otherwise it is a CUSTOM step with the text (`workup:: flash filtration through neutral aluminum oxide` → *flash filtration through neutral aluminum oxide; eluent: …*), and only `eluent::` without `workup::` also gives a CUSTOM step. Other workup steps that are written only in the procedure (washing, extraction, drying) are not exported.

  Before the export, enter your name and e-mail under **ORD export** in the plugin settings: ORD requires both for every record, and it becomes public when the dataset is published. These details are stored only on your computer, not in the vault. Each export is written to a new numbered folder, `Export/ORD/1/`, `2/` … (JSON; optionally also `.pbtxt`). A report then lists the reactions that were exported, those with warnings (e.g. no reaction time), and those that could not be exported, with the reason (e.g. a compound without an amount, a multi-step scheme, a structure RDKit cannot read); **Export anyway as draft** writes them too, to be completed in the ORD editor. Only single-step schemes are exported. Your notebook codes (the ChemDraw file name and the note name) are not written into the dataset; they are optional in ORD and can be added with the setting **Include notebook codes**. Submitting the dataset to ORD is done by hand (see the plugin's `README.md` and `ORD.md`, which also describe all rules in detail). The exports of the example notes, with their reports and the ord-schema validation, are in `docs/examples/`.

  **PubChem export.** From the same kind of note (a Dataview table of reaction notes), **Export products to PubChem from current table** prepares the products of a paper for deposition in [PubChem](https://pubchem.ncbi.nlm.nih.gov): one record per product with its structure as drawn (with stereochemistry; the same structure in several notes becomes one record only when its stereo meaning — as drawn, racemic or relative — is the same), `Name::` as the name, the compound number (`num_in_article::`) and the paper DOI. In the dialog enter the DOI, optionally a *hold until* date (the records stay private until then, at most one year) and the registry-ID prefix (also in the plugin settings, e.g. your lab code); a draft table shows which products are ready, which have warnings (no name, racemate …) and which cannot be exported (no compound number, R groups, labels not read). Each export goes to a new numbered folder, `Export/PubChem/1/`, `2/` …: an `.sdf` to upload, the same records as a PubChem spreadsheet (`_pubchem.csv`; one structure per row — a SMILES, or for a racemate an InChI with `/s3` (`/s2` for `rel-`); the `.sdf` is still the better upload because it keeps the drawn structure), a `_structures.tsv` for checking or the Supporting Information, and a report. Uploading is done by you in PubChem Submissions (New Submission → Substances; a new account is a test account until PubChem upgrades it). Each record gets a registry ID made of your prefix, the paper and the compound number (`LAB-jacs.6c08636-4a`), so every product needs `num_in_article::` (several products of one note: `4a, 4b`); notebook reaction codes are not published. A corrected export with the same IDs replaces the records; records can be changed or withdrawn in PubChem Submissions (**Modify** / **Revoke** under *Substances In PubChem*).
### Reminder
Creates reminders for a specific date. For example, it is configured to remind you to make a backup. The reminder is stored as a task in the [[Reminder]] note and repeats automatically every month. To create your own reminders, add a similar task with a reminder time to any note.

### TLC Photo Inbox
*Developed for this vault* (not in the Obsidian community plugin directory; included in the vault). Connects a Telegram bot of your own (created with @BotFather) to the vault, so that photos of TLC plates and other information can be sent from the phone. Telegram is only one suggested way to transfer photos from a phone and is optional. Alternatively, you can use the OneDrive mobile app (or another cloud storage app): upload the photo to a folder that is synchronized with your computer, or directly to the vault's **Files** folder if the vault itself is stored in OneDrive, and then drag or paste the image into the reaction note in Obsidian on the computer. In this case the image is inserted manually; automatic insertion into the TLC table works only through the Telegram workflow.

Press **📋 Reactions** in the bot (or **🔄 Update list**, which ends every message of the bot): it lists the 10 most recently created or edited notes of the **Journal** folder as buttons. Choose one and send one photo or one album: it is saved in **Files/telegram** as `A_122x….jpg` (the code the note name starts with) and removed from the chat; the plugin asks whether to add it (setting **Ask before inserting**), puts it into the first table of the note whose first row begins with `TLC` and moves it to **Files**; then the reaction is forgotten. You can also write the reaction code as the caption: `A_122`, or a caption that starts with a number, such as `122` or `122 after column`, if a **Default project** such as `PAS` is set (it becomes `PAS_122`; the whole album goes there). The rest of the caption is written under the photo in the same cell of the TLC table, on a new line: `A_122 Rf 0.3, hexane/EtOAc 3:1` gives the photo with *Rf 0.3, hexane/EtOAc 3:1* under it. After you choose a reaction, the caption is not read as a code: the photo goes to the chosen reaction with the whole caption under it (`2 SM` is text, not reaction `PAS_2`), also when you send it as a reply to the bot's message about that reaction. In an album only the photo with the caption gets the text. The text is written as plain text: it cannot break the table or add fields, tags or code. If the bot cannot tell the reaction, it keeps the photo and asks — reply with the code or press a reaction in the list. A photo you skip stays in **Files/telegram**; the command **Add photos from the Telegram inbox** asks again.

Everything else — a photo sent without a reaction, text, a link to an article, a PDF or another file — becomes a note named after the day of the message with the next free number (`Telegram/2026-10-16-1.md`, `-2`, …) with the text and `![[…]]` links to the attachments, which are saved in **Files**. Programs and scripts are refused. Messages sent while Obsidian is closed are handled in order when it opens (Telegram keeps them for 24 hours); the bot runs only in the desktop app.

Setup is in the plugin settings: paste the bot token, switch the bot on and pair your Telegram account with the one-time code shown there (see [[Welcome note]] for the steps). The token and the allowed users are stored only on this computer, not in the vault; the bot answers only paired users. The photos pass through Telegram's servers; the bot sends only note names, never structures or note contents.
### Template Guard
*Developed for this vault* (not in the Obsidian community plugin directory; included in the vault). Keeps the structure of the reaction notes. No setup is needed: Template Guard reads each project template (`Templates/Exp_.md`, also the templates of projects created later) and, in every note of that project (notes in **Journal** whose name starts with the project code, e.g. `Exp_12`):
- the template parts are protected while editing: section headings, field labels such as `**yield**::`, the note number with its value (`**id1**:: 005`), the structure of tables (pipes, the separator line and the first word of the header, e.g. `TLC`, by which the plugins find the table) the button blocks and the page break at the end of the note cannot be deleted by accident, and nothing can be appended to a heading (in the title `# Exp_12 Suzuki` only the code is fixed, the name after it can be edited), while values, table cells and the procedure stay editable. Click **🔒 Template** in the status bar to unlock one note when you want to change its structure;
- when a note is opened, missing template parts (and table rows with missing cells) are listed, and **Restore** puts them back in their place without changing anything else;
- when you add a field (or a heading, table or button) to the project template `Templates/Exp_.md` and save it, Template Guard offers to add it to all existing notes of the project, including the finished ones.
- when a field (or another part) is deleted from the project template, it is no longer protected or restored; existing notes keep it as ordinary text.

With the setting **Protect all Dataview fields**, the labels of all other fields of these notes (`key::`, `[key:: …]`) are protected too. A hotkey for the lock can be set in **Settings → Hotkeys** (*Template Guard: Lock / unlock the template in this note*).

Plugins that write into notes (CDX Scheme Image, TLC Photo Inbox, the NMR and Mass buttons, Templater) are not affected by the protection. Step-by-step guide with pictures: [[Template Guard guide]].
